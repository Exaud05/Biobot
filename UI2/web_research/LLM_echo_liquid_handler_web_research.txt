Echo pick list compatibility assessment for the Labcyte/Beckman Coulter Echo

What I searched and found
- Official Echo Cherry Pick user manual with the supported pick list (CSV) formats and the exact column headers the software recognizes. It also shows sample “explicit” pick lists with source/destination wells and a Transfer Volume column. ([s3images.coroflot.com](https://s3images.coroflot.com/user_files/individual_files/309705_ogsD0PcXsTzuVX9jRoSfGjfLa.pdf))
- Official specs confirming Echo 525 uses 25 nL droplets (i.e., volumes must be in 25 nL increments). ([beckman.com](https://www.beckman.com/liquid-handlers/echo-525?utm_source=openai))
- Documentation noting Echo 520/550/555 use 2.5 nL increments and the valid 384‑PP source plate volume range (2.5–10,000 nL, in 2.5 nL steps). ([manualslib.com](https://www.manualslib.com/manual/3856591/Labcyte-Echo-550.html?utm_source=openai))
- Real-world protocol examples that build Echo pick lists in CSV and map columns on import (e.g., Golden Gate assembly guide shows “Source Plate Name … Transfer Volume …” with volumes in nL and use of the Cherry Pick “Automap” during import). ([static.igem.org](https://static.igem.org/mediawiki/2021/0/01/T--Marburg--Golden_Gate_with_the_Echo_machine.pdf?utm_source=openai))

What Echo expects (from vendor docs)
- File type: CSV “pick list.” ([s3images.coroflot.com](https://s3images.coroflot.com/user_files/individual_files/309705_ogsD0PcXsTzuVX9jRoSfGjfLa.pdf))
- Recognized column headers (when using header-based import): Source Plate Barcode; Source Well; Destination Plate Barcode; Destination Well; Transfer Volume. If you do not use these exact headers, the data must match one of the documented column orders, or you must map the columns in the import dialog. ([s3images.coroflot.com](https://s3images.coroflot.com/user_files/individual_files/309705_ogsD0PcXsTzuVX9jRoSfGjfLa.pdf))
- Units/quantization: Transfer Volume is interpreted in nL, and must be an integer multiple of the instrument’s droplet size (2.5 nL on Echo 520/550/555; 25 nL on Echo 525). The valid range for common 384‑PP source plates is 2.5–10,000 nL on 2.5‑nL instruments. ([manualslib.com](https://www.manualslib.com/manual/3856591/Labcyte-Echo-550.html?utm_source=openai))
- Source labware: must be Echo‑qualified microplates; destination can be most SBS plates. ([s3images.coroflot.com](https://s3images.coroflot.com/user_files/individual_files/309705_ogsD0PcXsTzuVX9jRoSfGjfLa.pdf))

Comparison: your generated CSV vs. real Echo pick lists

Header row
- Yours: Source Plate Name, Source Plate Type, Source Well, Destination Plate Name, Destination Well, Transfer Volume, Sample ID.
- Echo-recognized headers: Source Plate Barcode, Source Well, Destination Plate Barcode, Destination Well, Transfer Volume. ([s3images.coroflot.com](https://s3images.coroflot.com/user_files/individual_files/309705_ogsD0PcXsTzuVX9jRoSfGjfLa.pdf))
- Assessment: Not a direct match. Cherry Pick can still import if you manually map columns (or use Automap) because “plate fields can contain barcode data or plate ID,” and community examples show successful mapping from “Source Plate Name/…/Transfer Volume” formats. However, the extra, non‑standard columns (Source Plate Type, Sample ID) are not recognized fields and must remain unmapped/ignored. If you attempt import without mapping and rely on column position, the extra column will break the expected order. ([s3images.coroflot.com](https://s3images.coroflot.com/user_files/individual_files/309705_ogsD0PcXsTzuVX9jRoSfGjfLa.pdf))

Transfer Volume values
- Your volumes (e.g., 810.0, 5430.0, 190.0 nL) appear to be expressed in nL and are multiples of 2.5 nL, which is valid for Echo 520/550/555. For Echo 525, many of these are not multiples of 25 nL and would be rejected (e.g., 810 nL ÷ 25 = 32.4, not allowed). ([manualslib.com](https://www.manualslib.com/manual/3856591/Labcyte-Echo-550.html?utm_source=openai))
- Magnitudes up to ~5,600 nL are within the 2.5–10,000 nL single‑transfer range shown for 384‑PP source plates on 2.5‑nL instruments. ([manualslib.com](https://www.manualslib.com/manual/3856591/Labcyte-Echo-550.html?utm_source=openai))

Well addressing and labware
- Wells are in standard A1…Pxx format (384‑well uses rows A–P, cols 1–24), which matches Echo conventions. Destination plate naming (“Destination Plate”) is acceptable if that string matches the destination plate ID/barcode defined in your protocol; otherwise the software will not find the plate. ([s3images.coroflot.com](https://s3images.coroflot.com/user_files/individual_files/309705_ogsD0PcXsTzuVX9jRoSfGjfLa.pdf))
- “Source Plate Type” set to “384 Well Plate” in your file is not a recognized pick‑list field. The actual source plate type/liquid class (e.g., 384PP_AQ_SP2) must be selected inside the protocol; it is not driven by the CSV unless specifically mapped by the application workflow. ([s3images.coroflot.com](https://s3images.coroflot.com/user_files/individual_files/309705_ogsD0PcXsTzuVX9jRoSfGjfLa.pdf))

Decision: will this file run as‑is on an Echo?
- If you load it in Echo Cherry Pick (or Plate Reformat) and use the import dialog to map “Source Plate Name → Source Plate Barcode,” “Destination Plate Name → Destination Plate Barcode,” “Source Well,” “Destination Well,” and “Transfer Volume,” then yes, the pick list is structurally plausible. The two extra columns will be ignored. This assumes you are running on a 2.5‑nL Echo (e.g., 550/555/650/655) and your protocol defines valid Echo‑qualified source plate types and an actual destination plate ID. ([s3images.coroflot.com](https://s3images.coroflot.com/user_files/individual_files/309705_ogsD0PcXsTzuVX9jRoSfGjfLa.pdf))
- It will not be accepted without changes on an Echo 525, because many Transfer Volume entries are not multiples of 25 nL (the 525’s droplet size). You would need to quantize each transfer to 25‑nL steps. ([beckman.com](https://www.beckman.com/liquid-handlers/echo-525?utm_source=openai))
- If you try to import this CSV without header mapping (i.e., rely on automatic header recognition or strict column order), it is likely to fail because your header names do not match the documented names and you include an extra column before Source Well. ([s3images.coroflot.com](https://s3images.coroflot.com/user_files/individual_files/309705_ogsD0PcXsTzuVX9jRoSfGjfLa.pdf))

Recommended minimal fixes before use
- Use (or map to) the documented header names: Source Plate Barcode, Source Well, Destination Plate Barcode, Destination Well, Transfer Volume. Keep extra columns un‑mapped. ([s3images.coroflot.com](https://s3images.coroflot.com/user_files/individual_files/309705_ogsD0PcXsTzuVX9jRoSfGjfLa.pdf))
- Confirm instrument model and quantize volumes accordingly:
  - Echo 520/550/555/650/655: multiples of 2.5 nL are OK.
  - Echo 525: convert all transfer volumes to multiples of 25 nL. ([manualslib.com](https://www.manualslib.com/manual/3856591/Labcyte-Echo-550.html?utm_source=openai))
- Ensure the protocol selects Echo‑qualified source plate types (e.g., 384‑PP variants) and that “Destination Plate Name” matches a plate ID/barcode defined in the run. ([s3images.coroflot.com](https://s3images.coroflot.com/user_files/individual_files/309705_ogsD0PcXsTzuVX9jRoSfGjfLa.pdf))

Bottom line
- Syntactic/structural plausibility: Plausible as a Cherry Pick pick list if you manually map the columns during import; not compliant with the “recognized header” set as‑written. ([s3images.coroflot.com](https://s3images.coroflot.com/user_files/individual_files/309705_ogsD0PcXsTzuVX9jRoSfGjfLa.pdf))
- Will it work? Yes on a 2.5‑nL Echo with proper column mapping and correct plate definitions; no on an Echo 525 unless you round all volumes to 25‑nL increments. ([manualslib.com](https://www.manualslib.com/manual/3856591/Labcyte-Echo-550.html?utm_source=openai))
